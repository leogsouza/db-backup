# db-backup v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar o CLI `db-backup` que faz dump MySQL, gzip e upload via rclone, apaga objetos antigos no remote, e sai diferente de 0 só se o dump ou o upload falharem.

**Architecture:** `internal/cli` valida flags. `internal/plan` é puro e monta argv, o objeto e a lista de retenção. `internal/run` executa o pipe sem shell, redação e sinais. `main` só mapeia exit codes. A Action composite builda o Dockerfile da raiz e roda o container.

**Tech Stack:** Go 1.26, stdlib apenas, mysql-community-client 8.4 LTS, rclone 1.75.2, Docker, GitHub composite action.

**Spec:** `docs/superpowers/specs/2026-10-19-db-backup-design.md`

## Global Constraints

- Módulo `github.com/leogsouza/db-backup`, `go 1.26`, sem dependência externa.
- Trabalhar só neste repo. Não mexer em venko-app nem em escala-voluntarios.
- `--driver` só aceita `mysql`.
- Argv do `mysqldump`, nesta ordem: binário, `--defaults-extra-file=<path>` primeiro, `--host=`, `--port=`, `--user=`, `--single-transaction`, `--routines`, `--triggers`, database posicional. Sem `--databases` e sem senha na argv.
- `gzip` sem argumentos. `rclone rcat <objeto>`. `rclone lsf --files-only <remote-dir>`. `rclone deletefile <objeto>`.
- Senha não entra em log, em `Error()`, em `String()`/`GoString()` nem na argv de filho. Filho herda o ambiente; o binário não lê nem reescreve `RCLONE_CONFIG`.
- Exit 2 uso inválido, antes de binário externo. Exit 1 falha de pipeline ou sinal. Exit 0 se os três processos passaram, mesmo com falha de retenção.
- Sucesso é silencioso. Log de falha vai para stderr com prefixo `db-backup:`.
- Nome do objeto em UTC, formato Go `20060102-1504`. Uma leitura de relógio por execução.
- Junção de remote sem `path.Join` e sem `filepath.Join`.
- `--port` default `3306`. `--keep` default `30`, unidade `24h`, comparação estrita `>`.
- Prefixo `^[A-Za-z0-9._-]+$`.
- Imagem `linux/amd64`: `golang:1.26-bookworm`, `debian:bookworm-slim`, `mysql-community-client` do componente `mysql-8.4-lts`, rclone `1.75.2`. Sem `USER`, sem wrapper shell, sem publish de registry, sem `LICENSE`.
- Action não recebe senha por input, não passa `--password`, não usa `set -x`, não faz checkout do repo chamador.

## Review Focus

- Dump ou gzip falha depois que o `rclone rcat` já começou a ler: a pessoa espera exit 1, o objeto parcial apagado e a retenção não rodando. Um objeto `.sql.gz` com nome válido e conteúdo truncado seria restaurado como backup bom. Teste em Task 4: `TestFailurePolicy`.
- `fmt` de `Options` ou erro de flag desconhecida com `--password=s3cret` vaza a senha no stderr do cron. A pessoa espera o texto de uso sem o segredo. Testes em Task 1: `TestOptionsTextOmitsPassword`, `TestUnknownFlagDoesNotEchoPassword`.
- `--keep 0`, ou o truncamento do nome ao minuto, apaga o objeto recém-enviado. A pessoa espera esse arquivo preservado. Teste em Task 2: `TestSelectExpiredKeepsCurrentAtKeepZero`.
- Senha com espaço ou `#` é cortada pelo defaults file e o dump autentica com senha errada, ou pior, com senha vazia. A pessoa espera o valor inteiro entre aspas. Teste em Task 2: `TestDefaultsFileQuotesPassword`.
- A Action imprime `DB_PASSWORD` ou `RCLONE_CONFIG`, ou passa `--password` na argv do `docker run`. A pessoa espera o secret mascarado e ausente da linha de comando. Verificação em Task 7: `grep` do `action.yml`.

func TestParsePasswordSources(t *testing.T) {
    without := removeFlag(baseArgs(), "--password")
    opts, err := Parse(without, func(k string) string {
        if k == "DB_PASSWORD" {
            return "from-env"
        }
        return ""
    })
    if err != nil || opts.Password != "from-env" {
        t.Fatalf("env: %v %q", err, opts.Password)
    }

    both := append(removeFlag(baseArgs(), "--password"), "--password=from-flag")
    opts, err = Parse(both, func(string) string { return "from-env" })
    if err != nil || opts.Password != "from-flag" {
        t.Fatalf("flag wins: %v %q", err, opts.Password)
    }

    emptyFlag := append(removeFlag(baseArgs(), "--password"), "--password=")
    opts, err = Parse(emptyFlag, func(string) string { return "from-env" })
    if err != nil || opts.Password != "" {
        t.Fatalf("empty flag wins: %v %q", err, opts.Password)
    }

    _, err = Parse(without, func(string) string { return "" })
    if err == nil || err.Error() != "db-backup: senha obrigatória via --password ou DB_PASSWORD" {
        t.Fatal(err)
    }
    _, err = Parse(without, func(k string) string {
        if k == "DB_PASSWORD" {
            return ""
        }
        return ""
    })
    if err == nil || err.Error() != "db-backup: senha obrigatória via --password ou DB_PASSWORD" {
        t.Fatal(err)
    }
}

- [ ] **Step 3: Implement policy and `Execute`**

`retentionAllowed` é `pipelineOK`. `mustDeletePartial` é `!pipelineOK`. `Execute` é o único chamador das duas.

Algoritmo de `Execute`, sem shell e sem setar `Cmd.Env`:

1. `signal.NotifyContext(ctx, syscall.SIGINT, syscall.SIGTERM)`. Cancelar no retorno.
2. `now := time.Now().UTC()` uma vez.
3. `os.CreateTemp("", "db-backup-client-*.cnf")`, `Chmod(0600)`, `defer os.Remove`. Se o temp falhar, devolver `errors.New("db-backup: backup falhou")` sem logar de novo: o `main` imprime o erro uma vez. Ainda não há objeto remoto.
4. `plan.Build`. Escrever `DefaultsFile`, fechar o arquivo antes de iniciar o filho.
5. Três `exec.CommandContext` com a argv do plano. Stdout do dump no stdin do gzip; stdout do gzip no stdin do rclone. Stderr de cada um num buffer. Não logar a argv.
